# WO-07: Perses replaces Grafana

**Status:** Approved for implementation (owner, 2026-10-08) · **Phase:** 1 · **Author:** Claude · **Implementer:** Codex
**Branch:** `codex/wo-07-perses` · **Decisions:** ADR-0030, ADR-0034

## Goal

Remove Grafana, which is AGPL-3.0. Its dashboards move to Perses (Apache-2.0, CNCF) as code, behind single sign-on.

## Verified context

- Grafana 13.2.3 is pinned in `lab/wsl/endpoints/artifacts.lock.json`. It is deployed through
  `tools/wsl_endpoints.py` and `tools/wsl_endpoints_gitops.py`, which generate `lab/wsl/endpoints/gitops/workloads.yaml`,
  and it is reached through `lab/wsl/endpoints/access.sh`.
- Grafana also appears in:
  - Module 3: `module-3/manifests/observability.yaml`, generated by `tools/render_module3.py`, and `module-3/README.md`.
  - Tools: `tools/wsl_endpoint_acceptance.py`, `tools/wsl_runtime_secrets.py` and `tools/ci/check_docs.py`.
  - Docs: ADR-0010, `docs/service-access.md` and the acceptance records.
- Baseline (ADR-0034): Perses 0.54.0 and Perses Operator 0.5.0. Both are pre-1.0, so pin them and test every upgrade.

## Scope

1. Add Perses and Perses Operator, digest-pinned and staged in the canonical registry path, through the
   generators. Restricted Pod Security, default-deny network policy, and allow rules only for
   Prometheus and the authentication path.
2. Authentication: Perses native OIDC with Keycloak, or the APISIX `openid-connect` pattern already used by the console.
   Choose one, record why in the PR, and allow no anonymous access.
3. Port every Grafana dashboard in the repo to Perses dashboards as code (Module 3, and the lab health
   dashboards). Add a Prometheus datasource.
4. Remove Grafana from lock files, generators, manifests, access scripts, secrets tooling and the acceptance tool.
   Keep the historical CI baselines passing; old revisions still contain Grafana.
5. Update the docs and the licence register. ADR-0010 points to ADR-0034 (WO-03).

## Out of scope

Jaeger, OpenSearch and the Prometheus LTS change, which belong to WO-10.

## Acceptance criteria

- Ported dashboards show live data in the lab. An unauthenticated request is refused, and a viewer role can view but not edit.
- No Grafana image or manifest remains. A CI check enforces this, and the licence register no longer lists it.
- Receipt: `docs/acceptance/perses-<date>.md`, with screenshots or page text for each dashboard.

## Owner actions

Approve the live lab change, which removes Grafana and deploys Perses.

## Report back

The authentication option chosen and why, the dashboard mapping (Grafana to Perses), and any panel that could not be ported.
